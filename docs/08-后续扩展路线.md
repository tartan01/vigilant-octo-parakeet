# 08 — 后续扩展路线

> 用户问过：以后要挂很多网站和资源，怎么构建？要不要装 Docker？
> 结论：Docker 不是必选项，取决于服务数量。按阶段平滑演进。

## 硬件条件

Windows 10 专业版 / 16GB 内存（可用约 7.7GB）/ 8 核 Xeon / 188GB 可用磁盘。三条路线都能走。

## 当前架构 vs 目标架构

**当前**：Cloudflare 一个 Public Hostname 直接指向本机 8080。每加一个服务要去 Cloudflare 加一条记录。

**目标**：引入反向代理层，Cloudflare 只保留一条入口指向 Caddy，由 Caddy 按子域名分发到各本地服务。以后加服务只改本机 Caddyfile，不碰 Cloudflare。

```
公网 → Cloudflare Tunnel → 127.0.0.1:2019(Caddy) → 网站A:8080 / 网站B:8081 / API:3000 / 文件:8082
                                                  → 数据层 SQLite/PostgreSQL/文件目录
```

## 三条路线

### 路线一：反向代理 + 多进程（推荐现在做）
- Caddy 分发，每服务一个端口，SYSTEM 任务自启
- 适合 10 个以内服务，零额外内存，现有技能即可
- Caddy 配置极简，三行一个服务：
  ```
  www.honoweb.com {
      reverse_proxy 127.0.0.1:8080
  }
  api.honoweb.com {
      reverse_proxy 127.0.0.1:3000
  }
  ```
- Cloudflare 侧把所有 hostname 指向 127.0.0.1:2019（Caddy 默认 HTTP 端口）即可

### 路线二：Docker Desktop（服务变多时）
- 容器隔离、docker-compose 一键编排、依赖不打架
- 适合 10–50 个服务，吃 2–4GB 内存
- 触发时机：服务间依赖冲突（一个要 Py3.10 一个要 3.13），或要快速复制整套环境
- Windows 上需 WSL2 支撑

### 路线三：WSL2 + Linux 原生 Docker（长期重度）
- 贴近生产环境、性能好、可用 systemd 生态
- 适合 50+ 服务或要复刻线上环境，学习曲线最陡

## 技术学习优先级

| 优先级 | 技术 | 解决什么 | 成本 |
|---|---|---|---|
| 必学 | 反向代理 Caddy | 一个入口分发多服务、自动 HTTPS、统一日志 | 半天 |
| 必学 | 端口与进程管理 | 服务独立端口、开机自启、崩溃重启 | 已在用 |
| 进阶 | Docker + compose | 服务隔离、环境一致、一键编排 | 1–2 周 |
| 进阶 | 数据库 SQLite→PostgreSQL | 数据存储需求 | 按需 |
| 按需 | Cloudflare R2 | "挂很多资源"——图片/文件不该塞本机 | 半天 |
| 远期 | Nginx / Linux 基础 | 迁正式服务器必备 | 长期 |

## 关于"挂很多资源"的重要提醒

图片、下载文件等**静态资源不要放本机硬盘**。推荐 Cloudflare R2：免费 10GB、无出口流量费，访问更快还省本机带宽和磁盘。本机只跑动态服务。

R2 免费版需要外币信用卡才能开通（历史搜索确认），国内用户开通有门槛；若开不了，静态资源可放 EdgeOne Pages 或保留在本机 `site/` 子目录。

## 数据安全

一旦网站有数据库或用户上传文件，需做备份。最简单：定时打包数据目录发到 R2 或另一台设备。16GB 内存够跑 PostgreSQL，但数据安全不能只靠本机单盘。

## 迁移到正式服务器的路径

用户原计划：访问量大了迁正式服务器。迁移时：
- 域名解析改一条记录即可（Cloudflare 侧），本机配置不用推倒重来
- 若届时走国内服务器 + 80/443，需先完成 ICP 备案
- 若用 Docker 编排，迁移成本最低（compose 文件搬过去即可）——这是提前上 Docker 的唯一强理由

## 四、服务器配置要点（理解架构，避免改错）

- **架构**：公网 → Cloudflare Tunnel → 本机 `127.0.0.1:8080`。本机只主动出站连接，不开放任何入站端口。运营商封 80/443 入站对本项目无影响。
- **隧道运行方式**：用 `cloudflared.exe tunnel run --token <TOKEN>` 直接运行进程，**不是** `service install`（后者因当时无管理员权限报 Access denied 而放弃）。功能等价，配合计划任务实现自启。
- **自启层级**：SYSTEM 账户 + AtStartup，开机即启动，不需用户登录。SYSTEM 进程在 Session 0，任务管理器里可能看不到，属正常，看 `logs/launch.log` 判断。
- **防重复**：`launch.ps1` 已保证计划任务触发与手动运行不会起第二套。历史上两个 pythonw 抢 8080、两个 cloudflared 用同一 Token 会造成连接抖动，已修复。
- **DNS 原理**：Public Hostname 本质是 CNAME 指向 `<隧道UUID>.cfargotunnel.com`，同一隧道所有 hostname 共用该目标。改错会导致 1033/1016 错误。

## 五、环境与权限约束（重要，别踩坑）

1. **本会话有安全沙箱**：历史上 `schtasks`、`wsl`、`wmic`、`cscript`/`wscript`、从 Bash 调 `powershell`、`Start-Process -Verb RunAs` 均被安全策略拦截。凡需提权或系统级操作，应写好脚本让用户本机双击/管理员运行，不要代执行。
2. **沙箱/普通权限查不到 SYSTEM 任务**：`Get-ScheduledTask -TaskName HomeServer-BootStart` 会报"找不到"，但任务真实存在。以 `logs/setup-log.txt` 或用户本机提权查询为准，切勿误判为失败后重复创建。
3. **bat 脚本必须纯 ASCII**：UTF-8 中文在 cmd.exe 按 GBK 解读会乱码导致命令损坏，历史已失败一次。PowerShell 脚本用 UTF-8 BOM 或纯 ASCII。
4. **端口探测用 TcpClient**：`Get-NetTCPConnection` 在计划任务脚本上下文返回空，命令行匹配 pythonw 也不可靠，最终用 `System.Net.Sockets.TcpClient.Connect('127.0.0.1',8080)` 最稳。
5. **替换文件用 `cp -f` 覆盖**：`rm` 被安全机制拦截过。
6. **不要真的重启用户电脑**（除非明确要求），会中断会话；用模拟验证代替。

## 七、扩展路线（用户认可的方向，供提案时参考）

- **现在阶段**：若服务增多，先引入 Caddy 反向代理。Cloudflare 只保留一条入口指向 Caddy，Caddy 按子域名分发到各本地端口。以后加网站只改本机 Caddyfile，不碰 Cloudflare。这是从单站到多站的关键一步，与 Docker 无关。
- **服务变多（10+）**：上 Docker Desktop + docker-compose 做容器隔离，代价是吃 2–4GB 内存、需 WSL2。
- **静态资源**：图片/下载文件不要放本机硬盘，优先 Cloudflare R2（免费 10GB、无出口流量费；但开通需外币信用卡，国内用户有门槛）。
- **数据安全**：有数据库或用户上传后要做备份（定时打包发 R2 或另一台设备）。
- **合规**：境外节点免备案但国内延迟 100–300ms，服务条款不适合大流量；正式对外经营需 ICP 备案并迁国内服务器。
